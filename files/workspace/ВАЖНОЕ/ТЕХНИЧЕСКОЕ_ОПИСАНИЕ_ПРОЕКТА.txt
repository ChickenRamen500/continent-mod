1. ОБЩАЯ КОНЦЕПЦИЯ
════════════════════════════════════════════════════════════════════════════

Continent Generator Mod — Fabric мод для Minecraft 1.20.1, который
генерирует процедурный мир на основе 7 пользовательских PNG карт
размером 3000×3000 пикселей.

Вместо ванильного шумового генератора, мод читает готовые карты мира
(высота, температура, влажность, эрозия, океаны, реки, озёра) и строит
рельеф, выбирает биомы и размещает воду напрямую по пикселям карты.

Пользователь может создать карты в любом графическом редакторе (GIMP,
Photoshop, QGIS) по заранее определённой цветовой схеме и получить
точный мир, повторяющий нарисованный контур.

Ключевое преимущество — полный контроль над миром: реальная карта Земли,
фэнтезийный континент, вымышленная планета — всё это возможно.

3. 7 PNG КАРТ — ФОРМАТ И НАЗНАЧЕНИЕ
════════════════════════════════════════════════════════════════════════════

Все карты должны быть размером 3000×3000 пикселей и лежать в папке
mods/continent-mod-maps/ (внутри директории запуска Minecraft,
обычно .minecraft/).

  ┌─────────────────┬──────────┬──────────────────────────────────────────┐
  │ Файл            │ Формат   │ Описание                                │
  ├─────────────────┼──────────┼──────────────────────────────────────────┤
  │ height.png      │ Grayscale│ Карта высот. 0 = MIN_Y (-64),          │
  │                 │ 8-bit    │ 255 = MAX_TERRAIN (200).                │
  │                 │          │ Формула: Y = MIN_Y + (h/255) *          │
  │                 │          │   (MAX_TERRAIN - MIN_Y)                  │
  │                 │          │ При worldSize=150000: 1 пиксель = 50     │
  │                 │          │ блоков. Билинейная интерполяция.         │
  ├─────────────────┼──────────┼──────────────────────────────────────────┤
  │ temperature.png │ RGB (24b)│ Цветовая палитра — 6 цветов по зонам:   │
  │                 │          │ ARCTIC=#7F8B99, SUBARCTIC=#88B4D7,      │
  │                 │          │ TEMPERATE=#6CC889, TROPICAL=#F7FB83,     │
  │                 │          │ SUBEQUATORIAL=#E7BD83, EQUATORIAL=#CE82  │
  │                 │          │ Матчится по ближайшему цвету (Euclidean  │
  │                 │          │ distance в RGB пространстве).            │
  ├─────────────────┼──────────┼──────────────────────────────────────────┤
  │ humidity.png     │ Grayscale│ Влажность: 0 = сухо, 255 = очень      │
  │                 │ 8-bit    │ влажно. Порог: <128 = сухо, >=128 =     │
  │                 │          │ влажно (2 корзины для биомов).           │
  ├─────────────────┼──────────┼──────────────────────────────────────────┤
  │ erosion.png     │ Grayscale│ Эрозия: 0 = острые пики/хребты,         │
  │                 │ 8-bit    │ 255 = плоские равнины.                   │
  │                 │          │ В текущей версии НЕ влияет на рельеф     │
  │                 │          │ (SimplexNoise удалён). Используется       │
  │                 │          │ BiomeParameters для отладки.               │
  ├─────────────────┼──────────┼──────────────────────────────────────────┤
  │ sea-ocean.png   │ RGBA     │ Маска океана/суши.                       │
  │                 │          │ 255 (в R-канале) = суша, <255 = океан.  │
  │                 │          │ OCEAN_THRESHOLD = 255.                   │
  │                 │          │ Глубокий океан (<= 80): рассчитывается   │
  │                 │          │ из глубины + удалённости от материка.     │
  │                 │          │ DEEP_OCEAN_THRESHOLD = 80.               │
  │                 │          │ getOceanNess() — билинейная интерполяция│
  │                 │          │ бинарной маски → плавные берега.        │
  ├─────────────────┼──────────┼──────────────────────────────────────────┤
  │ map_rivers.png  │ RGBA     │ Маска рек. RGBA изображение.             │
  │                 │          │ Вода = пиксель с alpha > 0 И             │
  │                 │          │ red < 128. Всё остальное = суша.        │
  │                 │          │ WATER_RED_THRESHOLD = 128.               │
  │                 │          │ Хранится как boolean[][] (true=вода).   │
  │                 │          │ getRiverNess() — билинейная [0..1].     │
  ├─────────────────┼──────────┼──────────────────────────────────────────┤
  │ map_lakes.png   │ RGBA     │ Маска озёр. Формат идентичен рекам.       │
  │                 │          │ getLakeNess() — билинейная [0..1].      │
  └─────────────────┴──────────┴──────────────────────────────────────────┘

 ВАЖНО: height.png использует СЖАТЫЙ диапазон (MAX_TERRAIN=200, НЕ 320).
  Это значит: 0 → Y=-64, 255 → Y=200 (высота 264 блоков, а не 384).
  Максимальная высота гор = Y=200, а не Y=320.

4. СИСТЕМА КООРДИНАТ И ТОРОИДАЛЬНОЕ ЗАМЫКАНИЕ
════════════════════════════════════════════════════════════════════════════

  Мировые координаты → пиксельные:
    pixelX = ((worldX + worldSize/2) / worldSize) * imageWidth
    pixelZ = ((worldZ + worldSize/2) / worldSize) * imageHeight

  Центр мира (0, 0) → центр картинки (1500, 1500).
  Левый край мира (-worldSize/2) → левый край картинки (0).
  Правый край мира (+worldSize/2) → правый край картинки (2999).

  Масштаб:
    blocksPerPixel = worldSize / imageWidth
    При worldSize=150000: blocksPerPixel = 150000/3000 = 50

  Тороидальное замыкание:
    Координаты пикселей оборачиваются через modulo:
      wrappedX = ((x % imageWidth) + imageWidth) % imageWidth
    Это позволяет переходить через край карты — левый край
    соединяется с правым, верхний с нижним (как на тороиде).

  Перенос между краями мира (Pac-Man эффект):
    WorldBorderHandler телепортирует игрока:
      x >= halfWorld → x - worldSize + 1
      x <= -halfWorld → x + worldSize - 1
    Предупреждение: эффект темноты за 50 блоков от границы.

6. MapData.java — ХРАНИЛИЩЕ КАРТ И ЗАПРОСОВ
════════════════════════════════════════════════════════════════════════════

  Файл: src/main/java/com/continentgen/map/MapData.java
  Строк: 337

  ОБЯЗАТЕЛЬНО singleton через MapLoader.getInstance().getMapData().
  НЕ хранит worldSize — передаётся как параметр в каждый метод.

  ─── Массивы данных (row-major, [z][x]) ───
    byte[][]    heightMap       — высота (grayscale 0-255)
    byte[][]    temperatureMap  — RGB ([z][x*3] = R,G,B)
    byte[][]    humidityMap     — влажность (grayscale 0-255)
    byte[][]    erosionMap      — эрозия (grayscale 0-255)
    byte[][]    seaOceanMap     — маска океана (grayscale)
    boolean[][] riversMask     — маска рек (true=вода)
    boolean[][] lakesMask      — маска озёр (true=вода)

  ─── Методы загрузки ───
    load(Path mapDir)     — Загружает 7 PNG из указанной папки.
                           Если файл не найден, заполняет дефолтом.
    parseGrayscale()      — Извлекает RED канал из ARGB.
    parseWaterMap()        — RGBA → boolean: alpha>0 AND red<128 = true.
    parseTemperature()     — RGBA → 3 байта RGB на пиксель.

  ─── Координатные преобразования ───
    toPixelX(worldX, worldSize)     — int: мировая → пиксельная (floor)
    toPixelZ(worldZ, worldSize)     — int: мировая → пиксельная (floor)
    toPixelXDouble(worldX, worldSize) — double: для билинейной
    toPixelZDouble(worldZ, worldSize) — double: для билинейной
    wrapX(x) / wrapZ(z)             — тороидальное замыкание
    getBlocksPerPixel(worldSize)    — масштаб: worldSize / imageWidth

  ─── Методы запроса (все принимают worldSize) ───

    getHeight(worldX, worldZ, worldSize) → int
      Билинейная интерполяция 4 соседних пикселей heightMap.
      Формула: MIN_Y + (h/255) * (MAX_TERRAIN - MIN_Y)
      Диапазон: -64 .. 200.

    getRiverNess(worldX, worldZ, worldSize) → double [0..1]
      Билинейная интерполяция riversMask (boolean → 0.0/1.0).
      1.0 = центр русла, 0.0 = суша далеко.
      НЕ использует circle-based поиск (was causing artifacts).

    getLakeNess(worldX, worldZ, worldSize) → double [0..1]
      Аналогично getRiverNess для озёр.

    isRiver(worldX, worldZ, worldSize) → boolean
      getRiverNess() >= RIVER_CHANNEL_THRESHOLD (0.5)

    isLake(worldX, worldZ, worldSize) → boolean
      getLakeNess() >= LAKE_CHANNEL_THRESHOLD (0.5)

    getOceanNess(worldX, worldZ, worldSize) → double [0..1]
      Билинейная интерполяция БИНАРНОЙ маски океана:
      seaOceanMap[pixel] < OCEAN_THRESHOLD (255) → 1.0, иначе 0.0.
      Плавный берег через bilinear blending.

    isOcean(worldX, worldZ, worldSize) → boolean
      seaOceanMap[pixel] < OCEAN_THRESHOLD (nearest-neighbour).

    isDeepOcean(worldX, worldZ, worldSize) → boolean
      seaOceanMap[pixel] <= DEEP_OCEAN_THRESHOLD (80).

    getSeaOceanDepth(worldX, worldZ, worldSize) → int [0..255]
      Сырое значение пикселя (nearest-neighbour).

    getClimateZone(worldX, worldZ, worldSize) → ClimateZone
      Пиксель temperature.png → RGB → nearest ClimateZone.

    getTemperature(worldX, worldZ, worldSize) → float [0..1]
      Температура климатической зоны.

    getHumidity(worldX, worldZ, worldSize) → int [0..255]
      Сырое значение humidity.png (nearest-neighbour).

    getErosion(worldX, worldZ, worldSize) → int [0..255]
      Сырое значение erosion.png (nearest-neighbour).

  ─── Нормализованные параметры (для BiomeParameters/debug) ───
    getTemperatureNorm() → double [-1..1]
    getHumidityNorm()     → double [-1..1]
    getContinentalness()  → double [-1.2..1.0]
      Формула: 0.6 - oceanNess * 1.8, clamp.
    getErosionNorm()      → double [-1..1]
    getWeirdness()        → 0.0 (фиксированный)
    getDepthNorm(y)       → double [-1..1]
      Формула: ((y - MIN_Y) / (MAX_Y - MIN_Y)) * 2.0 - 1.0

7. ContinentChunkGenerator.java — ГЕНЕРАЦИЯ РЕЛЬЕФА
════════════════════════════════════════════════════════════════════════════

  Файл: src/main/java/com/continentgen/world/ContinentChunkGenerator.java
  Строк: 296
  Наследует: net.minecraft.world.gen.chunk.ChunkGenerator

  ─── Константы генератора ───
    RIVER_DEPTH = 4              — Глубина русла реки (в блоках)
    LAKE_DEPTH = 3               — Глубина дна озера (в блоках)
    SURFACE_BLOCK_COUNT = 4      — Слои подповерхностных блоков (dirt/sand)
    RIVER_BANK_RANGE = 0.3       — Диапазон плавного берега
    LAKE_BANK_RANGE = 0.3

  ─── Instance fields ───
    worldSize (int)              — Размер мира, читается из BiomeSource
    mapData (MapData)            — Ссылка на singleton MapData
    seed (long)                  — Сид генерации

  ─── Ключевые методы ───
    getSeaLevel()    → MapData.SEA_LEVEL (63)
    getMinimumY()    → -64
    getWorldHeight() → 384

    populateNoise() — Главная точка входа.
      Для каждого чанка (16×16):
        1. Если карты не загружены → fallback (bedrock + stone + water).
        2. Иначе → generateColumn() для каждой колонки.
        3. populateBiomesSafe() — заполнение биомов в чанке.

    carve()         — No-op (предотвращает ванильные пещеры).
    buildSurface()  — No-op (поверхность уже в populateNoise).

  ─── ЛОГИКА generateColumn() (v5) ───

  Для каждой колонки вычисляются:
    terrainHeight = getHeight(worldX, worldZ, worldSize)
    oceanNess = getOceanNess(worldX, worldZ, worldSize)
    riverNess = getRiverNess(worldX, worldZ, worldSize)
    lakeNess = getLakeNess(worldX, worldZ, worldSize)

  Приоритет решения (от высшего к низшему):

  1. ОКЕАН (oceanNess >= 0.5):
     surfaceY = lerp(oceanFloor, terrainHeight, 1-oceanNess)
     waterSurfaceY = SEA_LEVEL (63)
     hasWater = true
     Пол плавно переходит от terrainHeight к oceanFloor.

  2. РУСЛО РЕКИ (riverNess >= 0.5):
     waterSurfaceY = SEA_LEVEL
     centerFactor = (riverNess - 0.5) / 0.5   — 0 на краю, 1 в центре
     depth = RIVER_DEPTH * centerFactor        — параболическое русло
     surfaceY = SEA_LEVEL - depth
     hasWater = true

  3. РУСЛО ОЗЕРА (lakeNess >= 0.5):
     Аналогично реке, но LAKE_DEPTH=3 (мельче).

  4. БЕРЕГ РЕКИ/ОЗЕРА (riverNess >= 0.2 ИЛИ lakeNess >= 0.2):
     bankNess = max(riverNess, lakeNess)
     blendFactor = (bankNess - 0.2) / 0.3    — [0..1]
     surfaceY = lerp(terrainHeight, SEA_LEVEL, blendFactor)
     Если surfaceY < SEA_LEVEL → hasWater.

  5. СУША (всё остальное):
     surfaceY = terrainHeight
     Если surfaceY < SEA_LEVEL → заливается водой.

  ─── Заполнение колонки ───
  От bottomY (-64) до max(surfaceY, waterSurfaceY):
    y > surfaceY И y <= waterSurfaceY  → WATER
    y == surfaceY                      → surface block (зависит от temp)
    y > surfaceY-4 И y > bottomY      → DIRT (суша) / GRAVEL (вода)
    остальное                          → STONE
    y == bottomY (-64)                 → BEDROCK (перезаписывает)

  ─── Surface Block выбор ───
    getSurfaceBlock(x, z, surfaceY):
      surfaceY <= seaLevel + 1 → SAND (пляж)
      temp < 0.15             → SNOW_BLOCK (арктика)
      temp > 0.85 & Y < 100   → SAND (пустыня/дюны)
      иначе                    → GRASS_BLOCK (трава)

    getUnderwaterSurfaceBlock(x, z, surfaceY):
      temp < 0.15 → DIRT
      иначе        → SAND

8. ContinentBiomeSource.java — ВЫБОР БИОМОВ
════════════════════════════════════════════════════════════════════════════

  Файл: src/main/java/com/continentgen/world/ContinentBiomeSource.java
  Строк: 366
  Наследует: net.minecraft.world.biome.source.BiomeSource

  ─── Codec Design ───
  MAP_CODEC = RecordCodecBuilder.mapCodec(
    instance.group(
      RegistryOps.getEntryLookupCodec(RegistryKeys.BIOME),  // biome registry
      Codec.LONG.optionalFieldOf("seed", 0L),
      Codec.INT.optionalFieldOf("world_size", DEFAULT_WORLD_SIZE)  // 150000
    ).apply(...)
  );
  CODEC = MAP_CODEC.codec();

  RegistryOps.getEntryLookupCodec() возвращает RecordCodecBuilder,
  а НЕ MapCodec — .forGetter() НЕ существует. Передаётся напрямую
  в instance.group(). Это паттерн vanilla MultiNoiseBiomeSource.

  ─── QUART-RESOLUTION FIX (критический!) ───
  BiomeSource.getBiome(int x, int y, int z, sampler) вызывается
  с QUART-RESOLUTION координатами: 1 единица = 4 блока.
  Vanilla BiomeAccess делает pos.getX() >> 2 перед вызовом getBiome.

  Наш FIX: blockX = x << 2; blockZ = z << 2; в начале getBiome().
  Без этого биомы попадали в 1/4 реальной позиции.

  ─── WORLD SIZE — PER-INSTANCE ───
  Каждый ContinentBiomeSource хранит СВОЙ worldSize (из codec JSON).
  MapData НЕ хранит worldSize — передаётся как параметр.
  Это фиксит баг с multiple instances перезаписывающими singleton.

  ─── Логика getBiome() ───

  Приоритет (от высшего к низшему):

  1. ВОДНЫЕ БИОМЫ (приоритет над сушей):
     a) oceanNess > 0.5 → getOceanBiome():
        deep ocean + cold → frozen_ocean
        deep ocean + warm → deep_ocean
        shallow + cold    → frozen_ocean
        shallow + cool    → cold_ocean
        shallow + warm    → ocean
     b) isRiver() → river (или frozen_river при temp < 0.15)
     c) isLake()  → swamp (или frozen_ocean при temp < 0.15)

  2. НАЗЕМНЫЕ БИОМЫ (BIOME_MATRIX):
     climateIdx = ClimateZone.ordinal()  → 0..5
     humIdx = (humidity < 128) ? 0 : 1  → 0=dry, 1=wet
     BIOME_MATRIX[climateIdx][humIdx] → biome key

  3. FALLBACK: plains (или первый элемент biomeEntries).

  ─── Разрешение биомов (biome resolution) ───
  resolveBiomeEntry(key):
    1. Сначала dynamic lookup через biomeRegistry.getOrThrow(key)
    2. При неудаче — static BuiltinRegistriesAccess.getBiomeEntry(key)
       (может дать ID=-1 на клиенте, но работает)

  Конструктор резолвит ВСЕ биомы при создании:
    12 наземных + 8 водных + 1 fallback (plains) = 21 entry.
  Логируется resolved/failed count.

11. WORLDBORDERHANDLER — ТОРОИДАЛЬНЫЕ ГРАНИЦЫ

  Файл: WorldBorderHandler.java (91 строк)

  Каждый тик для каждого игрока:
    1. Читает worldSize из world.getChunkManager().getChunkGenerator()
       (приведение к ContinentChunkGenerator).
    2. halfWorld = worldSize / 2.

       Если x <= -halfWorld → teleport(x + worldSize - 1)

  Результат: мир тороидальный — можно лететь бесконечно,
  левый край соединён с правым.

16. КЛЮЧЕВЫЕ АРХИТЕКТУРНЫЕ РЕШЕНИЯ
════════════════════════════════════════════════════════════════════════════

  1. БИЛИНЕЙНАЯ ИНТЕРПОЛЯЦИЯ
     Все маски (высота, реки, озёра, океан) используют билинейную
     интерполяцию 4 соседних пикселей. Это даёт плавную поверхность
     без ступеней и без кругов-артефактов.

     Метод: bilinearSample() для boolean масок,
     inline bilinear для byte масок (height, ocean).

  2. getRiverNess() / getLakeNess() [0..1]
     Вместо boolean isRiver() (который даёт резкие границы),
     билинейная интерполяция boolean маски → плавное значение [0..1].
     Это позволяет:
       - Параболическое русло (глубже в центре, мельче по краям)
       - Плавные берега (blendFactor)
       - Нет резких переходов

  3. PER-INSTANCE WORLD SIZE
     worldSize НЕ хранится в MapData (singleton).
     Каждый BiomeSource и ChunkGenerator хранит СВОЙ worldSize.
     Это предотвращает баг с несколькими instances при загрузке пресетов.

  4. QUART-RESOLUTION FIX
     BiomeSource.getBiome() получает координаты в 4× более грубом
     разрешении. Мы сдвигаем <<2 обратно к блочным координатам.

  5. BIOME MATRIX (2D lookup table)
     Вместо сложного multi-noise matching (vanilla approach),
     используем простую таблицу 6×2: ClimateZone × humidity bucket.
     Это ТОЧНО совпадает с map_locator.py → биомы в игре
     соответствуют предпросмотру.

  6. NO-OP carve() и buildSurface()
     carve() — пустой (нет ванильных пещер).
     buildSurface() — пустой (поверхность уже в populateNoise).

  7. PROTOCHUNK.populateBiomes()
     Стандартный API Yarn 1.20.1 для заполнения биомов в чанке.
     Вызывается ПОСЛЕ генерации колонок.
     Fallback: section-by-section populateBiomes().
