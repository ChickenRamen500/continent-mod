    28→    28→1. ОБЩАЯ КОНЦЕПЦИЯ
    29→    29→════════════════════════════════════════════════════════════════════════════
    30→    30→
    31→    31→Continent Generator Mod — Fabric мод для Minecraft 1.20.1, который
    32→    32→генерирует процедурный мир на основе 7 пользовательских PNG карт
    33→    33→размером 3000×3000 пикселей.
    34→    34→
    35→    35→Вместо ванильного шумового генератора, мод читает готовые карты мира
    36→    36→(высота, температура, влажность, эрозия, океаны, реки, озёра) и строит
    37→    37→рельеф, выбирает биомы и размещает воду напрямую по пикселям карты.
    38→    38→
    39→    39→Пользователь может создать карты в любом графическом редакторе (GIMP,
    40→    40→Photoshop, QGIS) по заранее определённой цветовой схеме и получить
    41→    41→точный мир, повторяющий нарисованный контур.
    42→    42→
    43→    43→Ключевое преимущество — полный контроль над миром: реальная карта Земли,
    44→    44→фэнтезийный континент, вымышленная планета — всё это возможно.

    72→    72→3. 7 PNG КАРТ — ФОРМАТ И НАЗНАЧЕНИЕ
    73→    73→════════════════════════════════════════════════════════════════════════════
    74→    74→
    75→    75→Все карты должны быть размером 3000×3000 пикселей и лежать в корневой
    76→    76→папке мира Minecraft (там же где level.dat, обычно .minecraft/run/).
    77→    77→
    78→    78→  ┌─────────────────┬──────────┬──────────────────────────────────────────┐
    79→    79→  │ Файл            │ Формат   │ Описание                                │
    80→    80→  ├─────────────────┼──────────┼──────────────────────────────────────────┤
    81→    81→  │ height.png      │ Grayscale│ Карта высот. 0 = MIN_Y (-64),          │
    82→    82→  │                 │ 8-bit    │ 255 = MAX_TERRAIN (200).                │
    83→    83→  │                 │          │ Формула: Y = MIN_Y + (h/255) *          │
    84→    84→  │                 │          │   (MAX_TERRAIN - MIN_Y)                  │
    85→    85→  │                 │          │ При worldSize=150000: 1 пиксель = 50     │
    86→    86→  │                 │          │ блоков. Билинейная интерполяция.         │
    87→    87→  ├─────────────────┼──────────┼──────────────────────────────────────────┤
    88→    88→  │ temperature.png │ RGB (24b)│ Цветовая палитра — 6 цветов по зонам:   │
    89→    89→  │                 │          │ ARCTIC=#7F8B99, SUBARCTIC=#88B4D7,      │
    90→    90→  │                 │          │ TEMPERATE=#6CC889, TROPICAL=#F7FB83,     │
    91→    91→  │                 │          │ SUBEQUATORIAL=#E7BD83, EQUATORIAL=#CE82  │
    92→    92→  │                 │          │ Матчится по ближайшему цвету (Euclidean  │
    93→    93→  │                 │          │ distance в RGB пространстве).            │
    94→    94→  ├─────────────────┼──────────┼──────────────────────────────────────────┤
    95→    95→  │ humidity.png     │ Grayscale│ Влажность: 0 = сухо, 255 = очень      │
    96→    96→  │                 │ 8-bit    │ влажно. Порог: <128 = сухо, >=128 =     │
    97→    97→  │                 │          │ влажно (2 корзины для биомов).           │
    98→    98→  ├─────────────────┼──────────┼──────────────────────────────────────────┤
    99→    99→  │ erosion.png     │ Grayscale│ Эрозия: 0 = острые пики/хребты,         │
   100→   100→  │                 │ 8-bit    │ 255 = плоские равнины.                   │
   101→   101→  │                 │          │ В текущей версии НЕ влияет на рельеф     │
   102→   102→  │                 │          │ (SimplexNoise удалён). Используется       │
   103→   103→  │                 │          │ BiomeParameters для отладки.               │
   104→   104→  ├─────────────────┼──────────┼──────────────────────────────────────────┤
   105→   105→  │ sea-ocean.png   │ Grayscale│ Маска океана/суши.                       │
   106→   106→  │                 │ 8-bit    │ 255 = суша, <255 = океан.               │
   107→   107→  │                 │          │ OCEAN_THRESHOLD = 255.                   │
   108→   108→  │                 │          │ Глубокий океан: значение <= 80.          │
   109→   109→  │                 │          │ getOceanNess() — билинейная интерполяция│
   110→   110→  │                 │          │ бинарной маски → плавные берега.        │
   111→   111→  ├─────────────────┼──────────┼──────────────────────────────────────────┤
   112→   112→  │ map_rivers.png  │ RGBA     │ Маска рек. RGBA изображение.             │
   113→   113→  │                 │          │ Вода = пиксель с alpha > 0 И             │
   114→   114→  │                 │          │ red < 128. Всё остальное = суша.        │
   115→   115→  │                 │          │ WATER_RED_THRESHOLD = 128.               │
   116→   116→  │                 │          │ Хранится как boolean[][] (true=вода).   │
   117→   117→  │                 │          │ getRiverNess() — билинейная [0..1].     │
   118→   118→  ├─────────────────┼──────────┼──────────────────────────────────────────┤
   119→   119→  │ map_lakes.png   │ RGBA     │ Маска озёр. Формат идентичен рекам.       │
   120→   120→  │                 │          │ getLakeNess() — билинейная [0..1].      │
   121→   121→  └─────────────────┴──────────┴──────────────────────────────────────────┘
   122→   122→
   123→   123→ ВАЖНО: height.png использует СЖАТЫЙ диапазон (MAX_TERRAIN=200, НЕ 320).
   124→   124→  Это значит: 0 → Y=-64, 255 → Y=200 (высота 264 блоков, а не 384).
   125→   125→  Максимальная высота гор = Y=200, а не Y=320.

   129→   129→4. СИСТЕМА КООРДИНАТ И ТОРОИДАЛЬНОЕ ЗАМЫКАНИЕ
   130→   130→════════════════════════════════════════════════════════════════════════════
   131→   131→
   132→   132→  Мировые координаты → пиксельные:
   133→   133→    pixelX = ((worldX + worldSize/2) / worldSize) * imageWidth
   134→   134→    pixelZ = ((worldZ + worldSize/2) / worldSize) * imageHeight
   135→   135→
   136→   136→  Центр мира (0, 0) → центр картинки (1500, 1500).
   137→   137→  Левый край мира (-worldSize/2) → левый край картинки (0).
   138→   138→  Правый край мира (+worldSize/2) → правый край картинки (2999).
   139→   139→
   140→   140→  Масштаб:
   141→   141→    blocksPerPixel = worldSize / imageWidth
   142→   142→    При worldSize=150000: blocksPerPixel = 150000/3000 = 50
   143→   143→
   144→   144→  Тороидальное замыкание:
   145→   145→    Координаты пикселей оборачиваются через modulo:
   146→   146→      wrappedX = ((x % imageWidth) + imageWidth) % imageWidth
   147→   147→    Это позволяет переходить через край карты — левый край
   148→   148→    соединяется с правым, верхний с нижним (как на тороиде).
   149→   149→
   150→   150→  Перенос между краями мира (Pac-Man эффект):
   151→   151→    WorldBorderHandler телепортирует игрока:
   152→   152→      x >= halfWorld → x - worldSize + 1
   153→   153→      x <= -halfWorld → x + worldSize - 1
   154→   154→    Предупреждение: эффект темноты за 50 блоков от границы.

   240→   240→6. MapData.java — ХРАНИЛИЩЕ КАРТ И ЗАПРОСОВ
   241→   241→════════════════════════════════════════════════════════════════════════════
   242→   242→
   243→   243→  Файл: src/main/java/com/continentgen/map/MapData.java
   244→   244→  Строк: 337
   245→   245→
   246→   246→  ОБЯЗАТЕЛЬНО singleton через MapLoader.getInstance().getMapData().
   247→   247→  НЕ хранит worldSize — передаётся как параметр в каждый метод.
   248→   248→
   249→   249→  ─── Массивы данных (row-major, [z][x]) ───
   250→   250→    byte[][]    heightMap       — высота (grayscale 0-255)
   251→   251→    byte[][]    temperatureMap  — RGB ([z][x*3] = R,G,B)
   252→   252→    byte[][]    humidityMap     — влажность (grayscale 0-255)
   253→   253→    byte[][]    erosionMap      — эрозия (grayscale 0-255)
   254→   254→    byte[][]    seaOceanMap     — маска океана (grayscale)
   255→   255→    boolean[][] riversMask     — маска рек (true=вода)
   256→   256→    boolean[][] lakesMask      — маска озёр (true=вода)
   257→   257→
   258→   258→  ─── Методы загрузки ───
   259→   259→    load(Path mapDir)     — Загружает 7 PNG из указанной папки.
   260→   260→                           Если файл не найден, заполняет дефолтом.
   261→   261→    parseGrayscale()      — Извлекает RED канал из ARGB.
   262→   262→    parseWaterMap()        — RGBA → boolean: alpha>0 AND red<128 = true.
   263→   263→    parseTemperature()     — RGBA → 3 байта RGB на пиксель.
   264→   264→
   265→   265→  ─── Координатные преобразования ───
   266→   266→    toPixelX(worldX, worldSize)     — int: мировая → пиксельная (floor)
   267→   267→    toPixelZ(worldZ, worldSize)     — int: мировая → пиксельная (floor)
   268→   268→    toPixelXDouble(worldX, worldSize) — double: для билинейной
   269→   269→    toPixelZDouble(worldZ, worldSize) — double: для билинейной
   270→   270→    wrapX(x) / wrapZ(z)             — тороидальное замыкание
   271→   271→    getBlocksPerPixel(worldSize)    — масштаб: worldSize / imageWidth
   272→   272→
   273→   273→  ─── Методы запроса (все принимают worldSize) ───
   274→   274→
   275→   275→    getHeight(worldX, worldZ, worldSize) → int
   276→   276→      Билинейная интерполяция 4 соседних пикселей heightMap.
   277→   277→      Формула: MIN_Y + (h/255) * (MAX_TERRAIN - MIN_Y)
   278→   278→      Диапазон: -64 .. 200.
   279→   279→
   280→   280→    getRiverNess(worldX, worldZ, worldSize) → double [0..1]
   281→   281→      Билинейная интерполяция riversMask (boolean → 0.0/1.0).
   282→   282→      1.0 = центр русла, 0.0 = суша далеко.
   283→   283→      НЕ использует circle-based поиск (was causing artifacts).
   284→   284→
   285→   285→    getLakeNess(worldX, worldZ, worldSize) → double [0..1]
   286→   286→      Аналогично getRiverNess для озёр.
   287→   287→
   288→   288→    isRiver(worldX, worldZ, worldSize) → boolean
   289→   289→      getRiverNess() >= RIVER_CHANNEL_THRESHOLD (0.5)
   290→   290→
   291→   291→    isLake(worldX, worldZ, worldSize) → boolean
   292→   292→      getLakeNess() >= LAKE_CHANNEL_THRESHOLD (0.5)
   293→   293→
   294→   294→    getOceanNess(worldX, worldZ, worldSize) → double [0..1]
   295→   295→      Билинейная интерполяция БИНАРНОЙ маски океана:
   296→   296→      seaOceanMap[pixel] < OCEAN_THRESHOLD (255) → 1.0, иначе 0.0.
   297→   297→      Плавный берег через bilinear blending.
   298→   298→
   299→   299→    isOcean(worldX, worldZ, worldSize) → boolean
   300→   300→      seaOceanMap[pixel] < OCEAN_THRESHOLD (nearest-neighbour).
   301→   301→
   302→   302→    isDeepOcean(worldX, worldZ, worldSize) → boolean
   303→   303→      seaOceanMap[pixel] <= DEEP_OCEAN_THRESHOLD (80).
   304→   304→
   305→   305→    getSeaOceanDepth(worldX, worldZ, worldSize) → int [0..255]

   365→   365→  ─── ЛОГИКА generateColumn() (v5) ───
   366→   366→
   367→   367→  Для каждой колонки вычисляются:
   368→   368→    terrainHeight = getHeight(worldX, worldZ, worldSize)
   369→   369→    oceanNess = getOceanNess(worldX, worldZ, worldSize)
   370→   370→    riverNess = getRiverNess(worldX, worldZ, worldSize)
   371→   371→    lakeNess = getLakeNess(worldX, worldZ, worldSize)
   372→   372→
   373→   373→  Приоритет решения (от высшего к низшему):
   374→   374→
   375→   375→  1. ОКЕАН (oceanNess >= 0.5):
   376→   376→     surfaceY = lerp(oceanFloor, terrainHeight, 1-oceanNess)
   377→   377→     waterSurfaceY = SEA_LEVEL (63)
   378→   378→     hasWater = true
   379→   379→     Пол плавно переходит от terrainHeight к oceanFloor.
   380→   380→
   381→   381→  2. РУСЛО РЕКИ (riverNess >= 0.5):
   382→   382→     waterSurfaceY = SEA_LEVEL
   383→   383→     centerFactor = (riverNess - 0.5) / 0.5   — 0 на краю, 1 в центре
   384→   384→     depth = RIVER_DEPTH * centerFactor        — параболическое русло
   385→   385→     surfaceY = SEA_LEVEL - depth
   386→   386→     hasWater = true
   387→   387→
   388→   388→  3. РУСЛО ОЗЕРА (lakeNess >= 0.5):
   389→   389→     Аналогично реке, но LAKE_DEPTH=3 (мельче).
   390→   390→
   391→   391→  4. БЕРЕГ РЕКИ/ОЗЕРА (riverNess >= 0.2 ИЛИ lakeNess >= 0.2):
   392→   392→     bankNess = max(riverNess, lakeNess)
   393→   393→     blendFactor = (bankNess - 0.2) / 0.3    — [0..1]
   394→   394→     surfaceY = lerp(terrainHeight, SEA_LEVEL, blendFactor)
   395→   395→     Если surfaceY < SEA_LEVEL → hasWater.
   396→   396→
   397→   397→  5. СУША (всё остальное):
   398→   398→     surfaceY = terrainHeight
   399→   399→     Если surfaceY < SEA_LEVEL → заливается водой.
   400→   400→
   401→   401→  ─── Заполнение колонки ───
   402→   402→  От bottomY (-64) до max(surfaceY, waterSurfaceY):
   403→   403→    y > surfaceY И y <= waterSurfaceY  → WATER
   404→   404→    y == surfaceY                      → surface block (зависит от temp)
   405→   405→    y > surfaceY-4 И y > bottomY      → DIRT (суша) / GRAVEL (вода)
   406→   406→    остальное                          → STONE
   407→   407→    y == bottomY (-64)                 → BEDROCK (перезаписывает)
   408→   408→
   409→   409→  ─── Surface Block выбор ───
   410→   410→    getSurfaceBlock(x, z, surfaceY):
   411→   411→      surfaceY <= seaLevel + 1 → SAND (пляж)
   412→   412→      temp < 0.15             → SNOW_BLOCK (арктика)
   413→   413→      temp > 0.85 & Y < 100   → SAND (пустыня/дюны)
   414→   414→      иначе                    → GRASS_BLOCK (трава)
   415→   415→
   416→   416→    getUnderwaterSurfaceBlock(x, z, surfaceY):
   417→   417→      temp < 0.15 → DIRT
   418→   418→      иначе        → SAND

   732→   732→16. КЛЮЧЕВЫЕ АРХИТЕКТУРНЫЕ РЕШЕНИЯ
   733→   733→════════════════════════════════════════════════════════════════════════════
   734→   734→
   735→   735→  1. БИЛИНЕЙНАЯ ИНТЕРПОЛЯЦИЯ
   736→   736→     Все маски (высота, реки, озёра, океан) используют билинейную
   737→   737→     интерполяцию 4 соседних пикселей. Это даёт плавную поверхность
   738→   738→     без ступеней и без кругов-артефактов.
   739→   739→
   740→   740→     Метод: bilinearSample() для boolean масок,
   741→   741→     inline bilinear для byte масок (height, ocean).
   742→   742→
   743→   743→  2. getRiverNess() / getLakeNess() [0..1]
   744→   744→     Вместо boolean isRiver() (который даёт резкие границы),
   745→   745→     билинейная интерполяция boolean маски → плавное значение [0..1].
   746→   746→     Это позволяет:
   747→   747→       - Параболическое русло (глубже в центре, мельче по краям)
   748→   748→       - Плавные берега (blendFactor)
   749→   749→       - Нет резких переходов
   750→   750→
   751→   751→  3. PER-INSTANCE WORLD SIZE
   752→   752→     worldSize НЕ хранится в MapData (singleton).
   753→   753→     Каждый BiomeSource и ChunkGenerator хранит СВОЙ worldSize.
   754→   754→     Это предотвращает баг с несколькими instances при загрузке пресетов.
   755→   755→
   756→   756→  4. QUART-RESOLUTION FIX
   757→   757→     BiomeSource.getBiome() получает координаты в 4× более грубом
   758→   758→     разрешении. Мы сдвигаем <<2 обратно к блочным координатам.
   759→   759→
   760→   760→  5. BIOME MATRIX (2D lookup table)
   761→   761→     Вместо сложного multi-noise matching (vanilla approach),
   762→   762→     используем простую таблицу 6×2: ClimateZone × humidity bucket.
   763→   763→     Это ТОЧНО совпадает с map_locator.py → биомы в игре
   764→   764→     соответствуют предпросмотру.
   765→   765→
   766→   766→  6. NO-OP carve() и buildSurface()
   767→   767→     carve() — пустой (нет ванильных пещер).
   768→   768→     buildSurface() — пустой (поверхность уже в populateNoise).
   769→   769→
   770→   770→  7. PROTOCHUNK.populateBiomes()
   771→   771→     Стандартный API Yarn 1.20.1 для заполнения биомов в чанке.
   772→   772→     Вызывается ПОСЛЕ генерации колонок.
   773→   773→     Fallback: section-by-section populateBiomes().
