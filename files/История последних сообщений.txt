quarter_negative(x): при x > 0 → 0 (воздух), при x < 0 → -x/4 (твёрдый блок). Точка пересечения = поверхность.

Стратегия «Terrain Carving» (по аналогии с Tectonic):
text

Для каждой колонки (worldX, worldZ):
  terrainHeight = getHeight(x, z)                    // из height.png
  riverNess     = getRiverNess(x, z)                 // 0..1, билинейная
  lakeNess      = getLakeNess(x, z)                   // 0..1, билинейная

  // Определяем локальную "водную поверхность" — ниже окружающей местности
  waterLevel = terrainHeight - CARVE_DEPTH * max(riverNess, lakeNess)

  // Дно русла ещё ниже (параболическое сечение)
  riverBed = waterLevel - RIVER_BOTTOM_DEPTH * riverNess
  lakeBed  = waterLevel - LAKE_BOTTOM_DEPTH * lakeNess

  surfaceY = max(riverBed, lakeBed, terrainHeight - bankBlend)
  waterSurfaceY = waterLevel
Идея: Вместо фиксированного SEA_LEVEL, вода следует за местностью — река в горах на Y=180, река на равнине на Y=70. Разница между окружающей местностью и водой = фиксированная (например, 3-8 блоков), НЕ 128 блоков.

Стратегия для берегов:
bankBlend: плавное понижение от terrainHeight к waterLevel в зоне берега (riverNess/lakeNess от 0.2 до 0.5)
Максимальный перепад на 1 пиксель ширины = контролируется через bilinear интерполяцию
Для кругов-артефактов:
Билинейная интерполяция УЖЕ реализована в MapData (getRiverNess, getLakeNess). Если круги остались, проблема скорее в:

Отсутствии нормалей/градиентов: реки не "врезаются" в террейн плавно, а просто заменяют блоки
